Trabajo Práctico Grupal: Gestionando un Proyecto Profesional

Integrantes 4 Estudiantes por equipo
Comienzo 20/10/2026
Duración 21 días (1 / 2 Sprints)

📌 Objetivos del TP

Gestionar en equipo un proyecto de software utilizando Jira, Confluence y Zephyr, bajo el marco de trabajo Scrum y utilizando UML para sentar las bases del desarrollo funcional.

Se Pide:

1

Configuración del Ecosistema de Trabajo

  • Confluence: Crear el espacio del proyecto con carátula profesional y formalidades del trabajo final.
  • Jira: Crear el proyecto para el grupo de trabajo, configurando el tablero Scrum.
  • Zephyr: Documentar Testing realizado del MVP.
2

Relevamiento y Documentación (En Confluence)

A partir del enunciado:

  • Definir el Objetivo del Sistema de Información.
  • Redactar Requerimientos Funcionales (RF) y No Funcionales (RNF).
  • Documentar el alcance del software.
  • Documentar testing con Zephyr.
3

Modelado de Software (UML)

Realizar los siguientes diagramas basados en una transacción principal del sistema:

  • Diagrama de Clases (MODP): Clases esenciales y de soporte para la transacción principal.
  • Diagrama de Casos de Uso: Foco en la interacción del usuario con la transacción.
  • Diagrama de Estados: Ciclo de vida de la transacción principal.
  • Diagrama de Componentes y Diagrama de Despliegue.
4

Gestión del Backlog (En Jira)

  • Cargar los RF de la transacción principal como Épicas e Historias de Usuario (HU).
  • Seleccionar las Épicas "Gestión Esencial / Gestión Transaccional" y desglosarlas con: Descripción, Criterios de Aceptación (BDD Gherkin para 2 HU esenciales con camino exitoso y un camino fallido a elección de cada una), Estimación (Story Points) y Prioridad.
  • Crear un repositorio para el código funcional y conectar Jira con Github for atlassian.
5

Ejecución del Desarrollo (Sprint 1 / 2 - Zephyr)

  • Configuración Inicial: Sprint 0 (Login + tareas técnicas).
  • Desarrollo Funcional: Elegir un mínimo de Historias de Usuario acorde para Sprint 1/2.
  • Testing (Zephyr): Documentar los casos de prueba asociados al desarrollo funcional y a HU con BDD Gherkin.
  • Entregable técnico: Código funcional con interfaz de usuario + Login conectado y subido a GitHub (repositorio público).

⚠️ Aclaración Importante para la Aprobación:

Flujo CI/CD: Es obligatorio que el proyecto refleje la aplicación de CI/CD, integrando este concepto fundamental en el repositorio de GitHub y su vinculación con Jira:

  • El código funcional del sistema debe estar alojado y actualizado en un repositorio de GitHub.
  • Dicho repositorio debe estar formalmente conectado con Jira mediante la aplicación GitHub for Atlassian.
  • Se debe presentar evidencia documentada y completa de la ejecución del testing en Zephyr.
